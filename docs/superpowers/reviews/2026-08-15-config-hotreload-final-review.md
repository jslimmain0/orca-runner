# 설정 핫로드 최종 리뷰 기록 (2026-08-15)

브랜치: feature/config-hotreload (ae44bd7..bdc6b22). 최종: 테스트 133/133, tsc 클린.

## 구현

- `Supervisor.applyConfig` — 반영 규칙 상태머신: 신규→DOWN 추가, 사라진 비활성→즉시 제거, 사라진 활성→유예(`설정에서 삭제됨` 표시, 중지 시 제거), def 변경→즉시 교체+실행 중이면 `⟳ r로 반영` 표시. `Entry.starting` 클레임 마커로 in-flight start 고아 레이스 차단.
- `configWatcher` — `~\.orca` 디렉토리 fs.watch(이벤트 기반, 주기 작업 0) + 500ms 디바운스. rename-replace 저장 감지.
- 대시보드/앱 — notice 줄(성공 5초/오류 스티키), 그룹 필터 유지, draw 단일 지점 sel 클램프, quit 시 워처 정리.

## 리뷰가 잡은 결함 (전부 수정)

- applyConfig↔start 레이스로 스폰 프로세스가 추적 밖 고아가 되는 경로 (클레임 마커)
- stopAll이 유예 삭제 엔트리에서 널 역참조로 크래시 — q 종료 흐름 파괴 (재현 확인)
- 유예 엔트리 삭제 후 sel 범위 이탈 → 키 입력으로 TUI 크래시
- BUILDING 중지 경로에서 유예 엔트리 미제거 (reapIfRemoved 헬퍼 통일)
- 무변경 성공 리로드가 스티키 오류 배너를 못 걷는 회귀 (수정 웨이브 자체가 만든 것 — 재리뷰가 잡음)
- 덤으로: s 연타 이중 스폰 잠재 레이스도 starting 가드로 봉인

## 파킹 (후속)

- 로그 뷰 보던 중 리로드로 목록 순서가 바뀌면 다른 서비스 로그로 조용히 전환될 수 있음 (index 기반 sel — 이름 기반 추적으로 개선 여지)
- 동일한 오류 메시지가 연속되면 diff 렌더러가 재출력하지 않음 (정보 손실 없음)
- 이중 스폰 가드 전용 테스트 부재
