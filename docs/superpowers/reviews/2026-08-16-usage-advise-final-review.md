# 사용량 추천 기능 최종 리뷰 기록 (2026-08-16)

브랜치: feature/usage-advise (6292157..d67853e). 최종: 테스트 158/158, tsc 클린. 최종 리뷰 판정 **머지 가능** (치명/중요 결함 0).

## 구현

- **수집**: RSS 피크는 기존 3초 tick에 편승해 누적, JVM 힙/메타/Full GC는 `jstat` 1회성 스냅샷(UP 후 90초 + 종료 시 — 발화 시점에 상태·pid 재검증). `~\.orca\usage.json`에 세션 간 누적(피크 max, FGC는 표본 수 분리 이동평균). jstat 부재 시 RSS-only 폴백. 주기 작업 추가 0 — 자원 예산 불변.
- **설정**: `metaspaceMb` 필드 신설(spring 기본 256, defaults.spring 지원) — 기존 하드코딩 해제.
- **추천**: 고정 수식(힙 90%↑/FGC>20 상향, 35%↓ 하향·128 스텝·최소 256 / 메타 85%↑·40%↓·64 스텝·최소 128), spring 전용, 하향은 관측 2세션 이상.
- **표면**: 대시보드 행 최하위 노트 `▼ 권장: 힙 512→256 ([v] 적용)`, `v` 키 = services.yaml 주석 보존 갱신 + 실행 중이면 자동 재시작, `orca advise`(라이브 jstat 병기, exit 계약: 정상+추천없음=0, 설정 오류/빈 목록=1).

## 과정에서 리뷰가 잡은 결함 (전부 수정)

- fgc 이동평균 분모 왜곡(jstat 실패 세션이 실측을 과소가중 — fgcSamples 분리)
- `orca advise`만 깨진 설정에서 exit 0(CLI 계약 위반 — status 패턴 정렬, 서브프로세스 계약 테스트 4개)
- m-off 세션의 jstat 데이터 유실(수집 키 유니온)

검증 하이라이트: Task 3 수동 E2E는 실제 JVM으로 `v` 적용 후 재시작된 프로세스의 커맨드라인(`-Xmx256m -XX:MaxMetaspaceSize=128m`)을 Win32_Process로 실증했고, 리뷰어가 트랜스크립트의 `⟳` 플리커를 코드 예측과 대조해 진위를 확인함.

## 파킹 (후속)
