# 설정 핫로드 설계 (2026-08-15)

대시보드가 떠 있는 동안 `~\.orca\services.yaml` 변경을 자동 감지해 반영한다. (사용자 승인: 방법 2 — fs.watch 자동 감지 + 아래 반영 규칙)

## 동작

- `fs.watch`로 **디렉토리**(`~\.orca`)를 감시하고 services.yaml 이벤트만 필터 (에디터의 rename-replace 저장도 잡기 위해 디렉토리 감시). 500ms 디바운스 후 재로드. 이벤트 기반이라 주기 작업 없음 — 자원 예산 영향 없음.
- 그룹 필터(`orca tspay`) 상태면 리로드 결과에도 같은 필터를 적용한다. 필터 결과가 비면 반영하지 않고 안내만.

## 반영 규칙 (Supervisor.applyConfig)

| 케이스 | 동작 |
|---|---|
| 새 서비스 | DOWN 행으로 추가 |
| 삭제된 서비스 (비활성) | 목록에서 즉시 제거 |
| 삭제된 서비스 (실행/빌드 중) | 관리 유지 + `(설정에서 삭제됨 — 중지 시 제거)` 표시, DOWN 도달 시 제거. start 재시도 거부 |
| def 변경 (비활성) | 조용히 교체 — 다음 시작부터 적용 |
| def 변경 (실행/빌드 중) | 새 def 저장 + `⟳ 설정 변경 — r로 반영` 표시, 다음 시작 시 표시 해제 |
| 파일 문법/검증 오류 | 기존 설정 유지 + `⚠ services.yaml 오류 — 기존 설정 유지: <사유>` 스티키 안내 |

- 리로드 성공 시 `설정 반영: +N 추가, M 변경, K 제거` 안내를 5초간 표시 (3초 tick에서 만료 처리 — 새 타이머 없음).
- 안내(notice)는 대시보드 head 아래 줄에 표시 (세션 재개 배너와 공존 가능).
- 서비스 수가 줄면 선택 커서(sel)를 범위 내로 클램프.
- 종료(quit) 시 워처 정리.

## 비목표

- 실행 중 서비스의 설정을 즉시 재적용(자동 재시작) — 위험해서 표시만.
- last-session/run.json 감시 — services.yaml만.
